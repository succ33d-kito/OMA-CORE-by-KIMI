# Prospective research capture on Linux Mint

This installs a **user-level, market-data-only** poller. It is not deployed by this ZIP and cannot run while the computer is asleep, shut down or booted into Windows. Missed receipts cannot be reconstructed as live observations. The research protocol remains frozen at `research/metrics_2024_2025/PROSPECTIVE_H1_PREREGISTRATION.json`.

1. Extract the ZIP on the Linux host. Create an isolated Python environment in the repository, then install the minimal runtime: `python3 -m venv .venv` and `.venv/bin/python -m pip install requests pandas numpy`.
2. Check that Binance Futures market-data access is authorized and works on that host. The optional adapter may need a Binance market-data API key for top-trader endpoints according to current documentation. Keep any key outside the repository; do not send it in chat or include it in command history. If used, create `~/.config/oma-core/prospective.env` containing `BINANCE_API_KEY=...` and restrict it to the user (`chmod 600`). Do not enable trading permissions for a research collector.
3. Run a source check before activation: `.venv/bin/python scripts/binance_research_collect.py ~/.local/share/oma-core/prospective/receipts.db --raw-dir ~/.local/share/oma-core/prospective/raw --preflight`. A 451, authentication error, mixed period or empty response blocks activation. The preflight writes no receipt.
4. Inspect proposed units: `.venv/bin/python scripts/install_prospective_timer.py --python .venv/bin/python --dry-run`. If they match the actual paths, run the same command with `--activate` instead of `--dry-run`. The unprivileged timer polls at UTC minutes 00,05,… with second 02. It records nothing before 2026-10-01 00:00 UTC. `Persistent=false` prevents a catch-up invocation after sleep or downtime.
5. Check the timer and health: `systemctl --user status oma-core-prospective.timer`, `journalctl --user -u oma-core-prospective.service --since today`, and `.venv/bin/python scripts/prospective_health.py ~/.local/share/oma-core/prospective/receipts.db`. Keep the laptop awake, on Linux and connected continuously. If the user systemd manager stops after logout, inspect its lingering configuration with `loginctl show-user "$USER" -p Linger` and arrange an authorized host configuration. Do not mistake a running timer for a complete feed.
6. Export audited inputs after enough real data accrue: `.venv/bin/python scripts/prospective_receipts.py export ~/.local/share/oma-core/prospective/receipts.db --out prospective_export`. Retain the SQLite ledger, raw responses, daily head hashes and exports separately. Then run the frozen gate on `prospective_export/prospective_bars.csv` and `prospective_export/prospective_metrics.csv`. Do not run a confirmatory gate unless the 90-day, N, receipt-time and completeness prerequisites pass.

The Work environment returned Binance HTTP 451. The optional Binance adapter was tested against fixtures, not a real successful endpoint session. Provider access, credentials where required, uninterrupted operation and source terms must be checked on the deployment host. A data archive downloaded later is not a substitute for actual receipt times. If the host cannot meet this, the prospective gate remains operationally blocked; registering a new start date requires a new protocol version before new outcomes are inspected.
